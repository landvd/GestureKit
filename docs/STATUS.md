## 2. 架构要点

- **线程**：事件 tap 在 `TapThread`（独立线程），引擎状态只在这条线程读写；识别在后台队列用规则快照算；
  UI（设置窗口、轨迹、HUD）在主线程。tap 不监听普通鼠标移动。详见 `CLAUDE.md`「线程模型」。
- **识别**：`Recognizer.swift`（纯函数）→ 结果同时执行动作并写 `GestureHistory`。学习数据在配置
  `learnedStrokes` / `rejectedStrokes`。
- **日志**：`~/Library/Application Support/GestureKit/gesturekit.log`，2MB 轮换；自检/基准写临时文件。

## 3. 测试与诊断命令

| 命令 | 用途 |
|---|---|
| `./build.sh [--install]` | 编译 + 文案检查 + 自检 + 签名（+ 安装） |
| `--selftest` | 全部断言 |
| `--perf` | 合成笔画的识别率 / 混淆、各环节耗时 |
| `--replay-history` | 用当前规则重放用户真实记录，评价当标准答案（只读）——调识别的主要依据 |
| `--tap-isolation-test` | 主线程卡 400ms 时光标事件延迟（应 < 20ms，约 3 秒） |
| `--ui-click-test` | 真实点击设置窗口每个侧栏/页签（约 30 秒，别动鼠标） |
| `GK_PERF=1` 启动 | 真实管线每 10 秒记录 tap 耗时与主线程卡顿 |
| `--ddc-probe` / `--ddc-test` | 外接屏 DDC 映射 / 只读亮度查询 |
